# portable-brain — переносимый «второй мозг» на Claude Code

Контейнер, который **несёт правила, а не данные**. Твои знания живут на хост-папке
`/brain`, а синхронизацию между машинами ты делаешь сам (git/облако). Образ легко
ставится на любую машину и уже «знает, как с тобой работать».

---

## Идея в одном абзаце

Образ Docker содержит только *как* работать: личность агента (`CLAUDE.md`), скиллы
(`запиши`/`вспомни`/`brain-init`), конвенции и детерминированные инструменты `brain`.
Сами знания — заметки по работе и личным вопросам — лежат на хосте в `/brain` и
переносятся тобой. Контейнер «приезжает» на новую машину уже умеющим тебя обслуживать,
а *что* ты знаешь — подтягивается вместе с данными.

## Три слоя

| Слой | Что это | Где живёт | Как переносится |
|---|---|---|---|
| Образ (правила) | `CLAUDE.md`, скиллы, конвенции, CLI `brain` | в Docker-образе | пересборка образа |
| Профиль | факты о тебе, как с тобой работать | `/brain/profile` | тобой, вместе с данными |
| Данные | заметки по проектам/жизни | `/brain/work`, `/brain/live` | тобой (git/облако) |

## Раскладка `/brain`

    /brain/profile   кто ты / как с тобой работать (живые факты)
    /brain/work      рабочее, sensitivity: confidential
    /brain/live      личное

Каждая область содержит:
- `.brain.yml` — **манифест** области (самоописание: что это, какой layout, уровень
  приватности, ключевые слова). Переносится вместе с данными.
- `MOC.md` — **индекс** заметок, который агент пересобирает автоматически.

Принцип именования заметок: `ГГГГ-ММ-ДД_тема-кебаб-кейс.md`, с frontmatter
(`date`, `tags`, `keywords`, `summary`, …).

## Как агент находит уже накопленное

Не сканируя всё подряд. Три уровня, каждый восстановим из нижнего:

    манифест (.brain.yml)  →  индекс (MOC.md)  →  frontmatter заметок

- **Самовосстановление:** если `MOC.md` устарел или пропал после ручного переноса
  файлов, агент пересобирает его из frontmatter (`brain index /brain/<область>`).
- **Recall:** по твоей фразе агент ищет по `keywords`/`summary`, показывает 2–3
  кандидата с однострочным описанием, и только после твоего выбора читает файл целиком.

## Граница приватности

У каждой области есть уровень: `public` < `personal` < `confidential`. Агент
**никогда не копирует** материал из более защищённой области в менее защищённую
(например, рабочий `confidential` не утечёт в личный `live`). Проверка встроена в
recall (`--into <уровень>`) и в скилл `запиши`.

## Запуск (подписка Claude Max/Pro)

1. Собрать образ (один раз, на машине с Docker):

       cd brain-image && docker build -t portable-brain .

2. Подготовить папку данных (один раз на каждом хосте):

       mkdir -p ~/brain

3. Запустить:

       docker run -it -v ~/brain:/brain portable-brain

4. Внутри Claude войти по подписке: `/login` → **Log in with Claude account** →
   подтвердить в браузере на хосте. **Не** задавай `ANTHROPIC_API_KEY` и **не**
   монтируй всю папку `/root/.claude` (перекроет вшитые правила и скиллы).

При старте контейнер сам создаёт области (`profile`/`work`/`live`) с манифестами —
это идемпотентно, существующие области не трогаются. Набор областей можно
переопределить: `-e BRAIN_AREAS="work:confidential live:personal"`.

Чтобы логин сохранялся между запусками — примонтируй только файл учётки:

    touch ~/brain-creds.json
    docker run -it -v ~/brain:/brain \
      -v ~/brain-creds.json:/root/.claude/.credentials.json portable-brain

## Повседневные сценарии

**Сохранить знание** — скажи «**сохрани**» / «запиши»:
> «Сохрани: настроил CI на GitHub Actions для Acme — npm ci, потом npm test и e2e.»

Агент определит область, создаст заметку с frontmatter и `keywords`, обновит индекс.

**Вспомнить прошлое** — сошлись на опыт:
> «На прошлом проекте я делал сервис авторизации — найди, как.»

Агент прогонит recall, покажет кандидатов, по выбору прочитает заметку и переиспользует.

## Перенос между машинами

Контейнер данные не синхронизирует — это делаешь ты:

    cd ~/brain && git init && git add . && git commit -m "snapshot" && git push
    # на другой машине:
    git clone <твой-приватный-репо> ~/brain

`work` и `live` можно держать в разных репозиториях/облаках — образ поддерживает
раздельные маунты.

## Инструменты `brain` (CLI, при желании напрямую)

    brain init <путь> --area ИМЯ --sensitivity УРОВЕНЬ   # создать область
    brain index <папка-области>                          # пересобрать MOC.md
    brain recall <корень> "<фраза>" [--into УРОВЕНЬ]      # поиск
    brain validate <файл>                                # проверить манифест/заметку
